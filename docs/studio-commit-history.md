# Studio: журнал мини-версий

В центре управления → «История изменений» по умолчанию открыт режим «Мини-версии». Режим «Релизы» сохраняет прежний ручной каталог крупных версий и фильтры.

- Один достижимый Git-коммит = одна мини-версия `DEV-<первые 8 символов SHA>`. Полный SHA — постоянный идентификатор, ссылка открывает diff.
- Дата коммита показывается в МСК; раскрытие показывает полное описание. Merge-коммиты помечены отдельно. Поиск работает по всему журналу, отображение порциями по 30.
- При каждой Web-сборке CI с полным checkout создаёт `studio/commit-history.json` из истории точного HEAD. Проверяются уникальность, полнота родителей и соответствие SHA метаданным сборки. Публичный deploy проверяет SHA журнала по HTTP.
- Отдельные незамерженные ветки, незакоммиченные правки, действия в локальных редакторах и тесты без коммитов не включены. Журнал не является доказательством успешности каждой исторической сборки. История относится к опубликованному снимку, а не к текущему состоянию удалённой ветки.
- Не менять номера крупных релизов ради каждого коммита. Для значимых инженерных действий создавать отдельный осмысленный коммит с описанием результата и проверок; тестовые и публикационные результаты фиксировать в сообщении коммита или PR.
- Для локального статического предпросмотра без build-meta.json журнал честно показывает отсутствие данных; архив релизов продолжает работать.

Проверка: `node --test tests/studio-commit-history.test.cjs`, `python scripts/build_studio_history.py build/web/studio/commit-history.json` (полная Git-копия). Затем открыть Studio, переключить вкладки, проверить поиск, раскрытие и загрузку следующих 30 записей.
