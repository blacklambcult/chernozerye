# Roadmap 3.0 — подтверждённая готовность

В `site/studio/releases.json` каждый из 18 пакетов содержит `criteria`: название, булево `done`, а для выполненных — `evidence` (путь к источнику, отчёт или ссылка на коммит/PR). Процент рассчитывается как floor(100 × выполненные критерии / все критерии). Четыре равновесных критерия на пакет — начальная инженерная декомпозиция, не оценка трудозатрат и не процент готовности всей игры.

Начальная оценка консервативна: зачтены только пункты, описанные в текущем журнале релизов, performance-roadmap-3.md и инфраструктуре Studio. Не проведён полный повторный аудит всех игровых подсистем; 0% означает отсутствие подтверждённых критериев в этом срезе, а не отсутствие существующих прототипов. Финальный критерий приёмки каждого пакета остаётся открытым до проверки.

После каждого инженерного пакета обновлять соответствующие criteria в том же PR, добавлять ссылку на фактическое подтверждение и фиксировать изменение в Git. Не повышать процент за написание непроверенного кода. Не изменять критерии ради увеличения процента. Roadmap 3.0 и история релизов остаются источниками структуры и контекста.

Проверки: node --test tests/studio-releases.test.cjs; в Studio раскрыть критерии каждого пакета, сравнить число выполненных и процент, проверить сохранность фильтров и истории мини-версий.
